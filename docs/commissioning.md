# Ввод в эксплуатацию

Последовательность действий перед допуском аппарата к работе на объекте.
Применимо и к первому прототипу, и к каждому новому экземпляру серии.

## 1. Входной контроль компонентов

- [ ] ESP32-S3 плата — проверить по `hardware/platforms.md`: соответствует
      ли реальная партия заявленным GPIO/ADC характеристикам (особенно
      важно для generic-клонов из `hardware/bom.csv`, где температурный
      диапазон -40...+85°C заявлен продавцом, а не датащитом)
- [ ] Батарея LiFePO4 48V 30Ah — проверить BMS-отсечку (должна совпадать
      с `SafetyLimits.min_battery_voltage = 42.0В`)
- [ ] Симистор BTA16-600B, датчик тока ACS758 — визуальный осмотр, проверка
      маркировки на соответствие BOM

## 2. Заводская калибровка (99 факт #95)

1. Калибровка делителя напряжения по эталонному вольтметру:
   - Подать известное опорное напряжение на вход измерительной цепи
   - Сверить показания АЦП с `VOLTAGE_DIVIDER_RATIO` в `firmware/main/measurements.c`
   - При отклонении >1% — скорректировать константу в прошивке
2. Калибровка датчика тока ACS758:
   - Подать известный ток через эталонную нагрузку
   - Сверить с `ACS758_MV_PER_AMP` и `ACS758_ZERO_CURRENT_MV`
3. Калибровка Zero-Cross детектора:
   - Осциллографом проверить, что прерывание срабатывает строго в момент
     перехода сетевого напряжения через ноль (задержка < 50мкс)

## 3. Функциональные тесты (безопасность)

Каждый пункт должен физически воспроизводиться и корректно обрабатываться:

| Тест | Ожидаемое поведение | Проверяется в коде |
|---|---|---|
| Отключить сварочный кабель во время нагрева | Мгновенное аварийное отключение (`OPEN_CIRCUIT`) | `tests/test_safety_validators.py::test_during_weld_detects_open_circuit` |
| Замкнуть сварочные контакты между собой | Аварийное отключение до превышения тока | `test_during_weld_detects_short_circuit` |
| Запустить сварку при разряженной батарее (<42В) | Блокировка старта, сообщение `BATTERY_LOW` | `test_pre_start_fails_low_battery` |
| Запустить сварку при поврежденном штрих-коде муфты (R не совпадает >10%) | Блокировка на этапе тестового импульса | `tests/test_welder_controller.py::test_resistance_mismatch_aborts_at_test_pulse` |
| Имитировать просадку сети до <185В | Блокировка старта | `test_pre_start_fails_low_voltage` |
| Проверить нагрев радиатора искусственным способом до >80°C | Аварийное отключение | `test_during_weld_detects_critical_overheat` |

## 4. Полевые испытания подготовки труб (СП 42-103-2003)

- [ ] Механическая очистка скребком — визуальная проверка снятия оксидного
      слоя (0.1-0.2мм) перед первой производственной сваркой
- [ ] Позиционер — проверка жесткой фиксации труб
- [ ] Обезжиривание изопропиловым спиртом — используется безворсовая
      салфетка

`critical_analysis/standards_checker.py::check_preparation` формализует эту
проверку в коде и должна использоваться на этапе HMI-подтверждения перед
стартом сварки (интеграция с UI — вне текущего каркаса прошивки).

## 5. Пробная сварка на бракованном образце

Перед вводом в эксплуатацию на реальном объекте — минимум 3 пробные сварки
на отбракованных трубах/муфтах того же типоразмера, с последующим
разрезом соединения и визуальной оценкой прогрева (равномерность
выдавливания расплава по периметру, отсутствие следов недогрева/перегрева).

## 6. Регламент обслуживания

Согласно 99 факту #94: счетчик дней до следующего ТО (по умолчанию 365
дней) должен быть виден в сервисном меню. При превышении срока —
аппарат обязан выдавать предупреждение при старте (не блокирует работу,
но требует подтверждения оператора).

## Ограничения текущего статуса проекта

Данный документ описывает процедуру для **готового физического
прототипа**. На момент написания:

- Прошивка не скомпилирована и не прошита на реальное железо
  (см. `firmware/README.md`)
- Корпус и герметичность не испытаны физически (см. `docs/safety_analysis.md`, риск #11)
- Заводская калибровка не может быть выполнена без собранного стенда

Ввод в эксплуатацию в описанном виде возможен только после сборки первого
физического прототипа по BOM (`hardware/bom.csv`) и переноса прошивки на
реальный esp-idf toolchain.
