# Прошивка ESP32-S3 (esp-idf)

## Статус

Это референсный каркас прошивки, портирующий уже протестированную
Python-логику (`simulation/`, `control/`) на C для ESP32-S3 в среде esp-idf.

**Важная оговорка**: в среде разработки, где написан этот код, недоступен
инструментарий esp-idf (`idf.py`, `xtensa-esp32s3-elf-gcc`), поэтому файлы
**не были скомпилированы и не проверены на реальном оборудовании**. Логика
ПИД-регулятора (`pid_controller.c`) и конечного автомата (`state_machine.c`)
зеркалирует Python-версии, покрытые 70 автотестами (`tests/`), но C-порт
сам по себе требует:

1. Установки esp-idf v5.x (`get_idf` / `install.sh`)
2. Сборки: `idf.py set-target esp32s3 && idf.py build`
3. Прошивки и тестирования на реальной плате (см. `hardware/platforms.md`
   для выбора платы) перед использованием в силовой части

## Известные незавершенные интеграции

- `measurements.c`: чтение DS18B20 (температура) — заглушка, требует
  подключения компонента 1-Wire (например, `espressif/ds18b20` из ESP
  Component Registry) вместо самописного побитового драйвера.
- `zero_crossing.c`: ISR-обработчик перехода через ноль сейчас пустой —
  в текущей схеме `app_main.c` цикл управления опрашивается периодической
  FreeRTOS задачей (~50 Гц) вместо event-driven запуска из самого
  прерывания. Для продакшена рекомендуется перейти на event-driven схему
  через `xQueueSendFromISR` для минимизации джиттера синхронизации.
- Штрих-код сканер, дисплей, SD-логирование, Wi-Fi/BLE — не реализованы
  в этом каркасе, см. `docs/architecture.md` за планом разбиения на задачи.
